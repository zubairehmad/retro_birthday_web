# Patch Task 5.4: Convert Photo Album to Responsive Memories

## Reason for Change

The media destination should be a Memories page rather than a photo-only album. It must support videos from the data source and provide an intentional desktop layout in addition to the existing mobile presentation.

## Updated Requirements

1. Rename the visible destination and page heading to Memories.
2. Read image and video entries from `birthdayData.js`.
3. Render media in a centered responsive desktop grid whose columns adapt to available width.
4. Render media in a centered single vertical column on mobile.
5. Preserve category tabs, Polaroid styling, lightbox behavior, lazy media loading, and back navigation.
6. Cap individual desktop cards and preserve media proportions instead of stretching or cropping images.
7. Increase the mobile card and image presentation for readable photos.

## Boundaries / Impact

- Affected files: `src/screens/MainScreen.jsx`, `src/screens/PhotoAlbum.jsx`, `src/components/PolaroidCard.jsx`, `src/components/PhotoLightbox.jsx`, `src/data/birthdayData.js`, and relevant `src/App.css` rules.
- Do not change unrelated screens or navigation state names.

## Acceptance Criteria

- Main navigation and page heading say Memories.
- Image and video entries can be configured in `birthdayData.js`.
- Desktop media is centered in a responsive multi-column grid.
- Mobile media is centered in one vertical column.
- Video entries render with native controls and remain accessible.
- Desktop cards remain individually capped and centered within the responsive grid.
- Desktop previews preserve image proportions.
- Mobile previews are visibly larger while remaining within the viewport.
