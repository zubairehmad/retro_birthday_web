# Patch Task 2.12: Fix Sound Effect Playback

## Reason for Change

The `yay` and `nooo` sound effects are not being heard because `playSound` is throwing an unknown exception during sound-effect playback. The shared helper must be corrected so user-triggered effects play reliably without leaking failures into the UI interaction flow.

## Updated Requirements

1. Inspect and correct the root cause of the unknown exception in `src/utils/audio.js`.
2. Ensure `playSound(src)` constructs and starts valid sound-effect assets reliably after a user gesture.
3. Handle synchronous construction errors and asynchronous playback rejections explicitly without unhandled exceptions or broken button interactions.
4. Preserve the existing `yay.mp3` and `nooo.mp3` paths, button timing, mobile/desktop behavior, and non-blocking UX.
5. Keep failure handling consistent with the existing audio utility contract; do not silently convert successful playback into a no-op.

## Boundaries / Impact

- Affected files: `src/utils/audio.js` and, only if required to correct the call contract, the existing initial-screen sound call sites.
- Do not alter emoji rain, NO-button movement, navigation, music-player behavior, or unrelated screen logic.
- Do not add external audio libraries or change asset locations.
- Do not edit completed audio or celebration task files.

## Acceptance Criteria

- Clicking YESS! successfully attempts and plays the valid `yay.mp3` effect without an unknown exception.
- Tapping NO on supported mobile/touch input successfully attempts and plays the valid `nooo.mp3` effect without an unknown exception.
- Synchronous audio-construction errors and asynchronous `play()` rejections are handled explicitly without unhandled promise rejections.
- Sound failures do not crash, block, or change the existing celebration, navigation, or sad-reaction flows.
- Existing music playback and audio fallback behavior remain unaffected.
