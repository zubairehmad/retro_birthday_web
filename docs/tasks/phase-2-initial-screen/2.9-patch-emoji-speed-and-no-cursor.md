# Patch Task 2.9: Improve Emoji Speed and NO Cursor Evasion

## Reason for Change

The current emoji rain feels too slow, and the desktop NO button does not consistently avoid an approaching mouse cursor because pointer tracking is limited to the button's narrow interaction wrapper.

## Updated Requirements

1. Increase the happy and sad emoji rain fall speed so visible particle trajectories complete in approximately 1.5–2.5 seconds.
2. Preserve short, staggered particle delays while ensuring the overall celebration remains lively.
3. Track desktop mouse coordinates across the full initial-card interaction area, including cursor movement before it reaches the NO button.
4. Recalculate a safe relative NO-button position when the cursor enters the configured proximity threshold.
5. Keep the NO button fully inside its bounded interaction container and preserve mobile touch behavior separately.

## Boundaries / Impact

- Affected files: `src/components/EmojiRain.jsx`, `src/screens/InitialScreen.jsx`, and related `src/App.css` styles.
- Do not change audio utility behavior, YES navigation, mobile sad-reaction behavior, or the root-level celebration lifecycle.
- Do not add external routing, animation, or state-management dependencies.

## Acceptance Criteria

- Happy and sad emoji particles fall noticeably faster and complete their trajectories within the updated 1.5–2.5 second target.
- Moving the mouse toward NO anywhere within the initial card interaction area causes the button to evade before the cursor reaches it.
- NO-button movement remains bounded, smooth, and free of horizontal overflow.
- Mobile NO taps still trigger the sad sound/emoji reaction without desktop cursor tracking.
