# Patch Task 2.11: Vary Emoji Rain and Restore NO Position

## Reason for Change

The emoji set and density are sufficient, but the current trajectories can look like a synchronized cluster falling straight down instead of natural rain. The desktop NO button also remains displaced after the cursor leaves its interaction area.

## Updated Requirements

1. Vary each emoji particle's bounded start position, size, speed, delay, horizontal drift, and rotation so the overall effect resembles lively, natural rain.
2. Preserve the existing emoji variety, brisk 1.5–2.5 second trajectory target, density cap, pointer transparency, and cleanup behavior.
3. Keep particle variation visually balanced and performant without introducing unbounded timers, elements, or external animation dependencies.
4. Detect when a desktop pointer leaves the NO button's configured interaction/proximity area and smoothly restore the button to its original transform position.
5. Cancel or supersede a pending reset when the pointer re-enters the proximity area so movement remains responsive and free of competing updates.
6. Preserve strict parent-container bounds, no horizontal overflow, smooth transforms, and separate coarse/touch-pointer behavior.

## Boundaries / Impact

- Affected files: `src/components/EmojiRain.jsx`, `src/screens/InitialScreen.jsx`, and related `src/App.css` styles.
- Do not alter emoji data, navigation destinations, audio utility behavior, root-level celebration ownership, or unrelated screens.
- Do not edit completed 2.5, 2.7, 2.9, or 2.10 task files.
- Do not add external dependencies or unbounded particle generation.

## Acceptance Criteria

- Happy and sad emoji particles visibly use varied trajectories rather than falling as a synchronized vertical cluster.
- Particle variation remains bounded, performant, pointer-transparent, and compatible with the existing 1.5–2.5 second timing target and cleanup lifecycle.
- Desktop NO movement remains directional, smooth, and strictly bounded while the pointer is within the configured interaction/proximity area.
- After the desktop pointer leaves that area, the NO button smoothly returns to its original position.
- Re-entering the area during reset produces one coherent current movement without jitter or competing reset updates.
- Mobile/touch NO taps continue to play the existing sound and show sad emoji feedback without desktop cursor evasion.
