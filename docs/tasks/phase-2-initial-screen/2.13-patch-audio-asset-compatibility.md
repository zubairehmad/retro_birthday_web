# Patch Task 2.13: Fix Audio Asset Compatibility

## Reason for Change

The browser reports `NotSupportedError: Failed to load because no supported source was found` for `yay.mp3`. The configured effects directory is empty, so the browser cannot load the requested source. The fix uses small browser-supported WAV assets and updates the initial-screen paths rather than treating the missing source as a playback-helper exception.

## Updated Requirements

1. Inspect the configured `yay.mp3` and `nooo.mp3` paths and the files served from those paths.
2. Provide valid `yay.wav` and `nooo.wav` sound-effect assets using a browser-supported audio container and codec.
3. Verify that the Vite public-asset paths resolve correctly in development and production builds.
4. Preserve the hardened `playSound(src)` handling so unsupported, missing, or blocked sources never produce unhandled exceptions.
5. Keep playback user-gesture initiated and preserve existing YES/NO timing, mobile behavior, and non-blocking fallback behavior.

## Boundaries / Impact

- Affected files: `public/assets/audio/effects/` sound assets, `src/utils/audio.js`, and only the relevant documentation or call sites if path correction is required.
- Do not alter emoji rain, NO-button movement, navigation, music-player behavior, or unrelated screen logic.
- Do not add external audio libraries or change the public asset strategy.
- Do not edit completed audio task files or replace valid assets unnecessarily.

## Acceptance Criteria

- `yay.wav` and `nooo.wav` resolve at the paths used by the initial-screen handlers.
- Both effect files use an audio format supported by the target browsers and play after their respective user gestures.
- The browser no longer reports `NotSupportedError` caused by missing, invalid, or undecodable effect sources.
- Missing, unsupported, or blocked audio remains explicitly handled without unhandled promise rejections or broken interactions.
- Existing music playback and all non-audio flows remain unaffected.
