# Patch Task 3.11: Add Looping HBD Background Birthday Song

## Reason for Change

When the user reaches the HBD Screen, the existing birthday song should provide a continuous celebratory background. The supplied `happy_birthday.mp3` must be limited to the HBD experience, loop while that screen is active, and stop cleanly when the user navigates away.

## Updated Requirements

1. Start `public/assets/audio/songs/happy_birthday.mp3` when the user reaches the HBD Screen.
2. Keep the song looping for the full duration of the HBD Screen session.
3. Stop playback and release audio resources when leaving HBD, including navigation to the Main Screen or any other destination.
4. Scope this background player exclusively to HBD; it must not start on Initial, Main, Album, Letter, or Music screens.
5. Respect browser autoplay and user-gesture restrictions. A blocked or rejected playback attempt must be handled explicitly without preventing HBD rendering, emoji rain, cake interaction, or navigation.
6. Avoid duplicate audio instances, overlapping loops, stale event listeners, and playback continuing after unmount.
7. Preserve existing cake sound effects, celebration rain, quote rotation, responsive layout, and unrelated Music Page playback behavior.

## Boundaries / Impact

- Affected files: `src/screens/HbdScreen.jsx`, `src/utils/audio.js` or a narrowly scoped audio helper if required, and related documentation/configuration only.
- Use the existing bundled song path and established audio error-handling conventions.
- Do not alter the song asset, screen navigation model, emoji-rain implementation, cake interaction semantics, or unrelated screen audio.
- Do not edit completed 3.4, 3.6, 3.7, 3.8, or 3.9 task files.
- Do not add external dependencies or introduce a global always-on audio player.

## Acceptance Criteria

- Entering HBD attempts to play `happy_birthday.mp3` as background music.
- The song loops continuously while HBD is active.
- Leaving HBD stops playback, removes listeners, and releases the player without audio leakage.
- No background song starts on Initial, Main, Album, Letter, or Music screens.
- Re-entering HBD creates at most one active HBD music instance and restarts or resumes according to the implemented lifecycle contract without overlap.
- Autoplay rejection or unsupported playback is surfaced through the existing safe handling path and does not break rendering or user interactions.
- Existing cake pop audio, emoji rain, quote rotation, navigation, and responsive behavior remain intact.
